I'm pleased to announce the v0.3.x line of Grove — three published releases (`0.3.1`, `0.3.2`, `0.3.4`) that collectively close out a long-running rethink of what a Grove install actually is.

This is the changelog post for everything that landed between June 25 and July 23, 2026 — 348 files, ~5,800 insertions, ~13,000 deletions. Most of the deletions are good news: they mean we finally stopped carrying a "V1 bundle" that tried to be every framework and every surface at once.

## TL;DR

- **V1 → directory toolkit.** We split the old monolith into `@grove-dev/core` (headless engine) and `@grove-dev/astro` (Astro adapter + consumer-owned pages). `nextjs`, `svelte`, `ui`, and the package-owned `templates/default/` scaffold are gone.
- **A browser-safe `@grove-dev/core/directory` entry point** with eight focused modules — search, lenses, display, format, scores, repo, taxonomy, and a thin client.
- **CLI narrows to four commands** — `init`, `check`, `sync`, `cleanup` — each named after the part of the lifecycle it owns.
- **The docs site gets a real home.** A standalone Astro + Tailwind landing route, honest framework status, real CLI commands, full OG / Twitter / JSON-LD metadata, and PWA + SEO assets for `grove.dev.mn`.
- **JSON-LD you can trust.** We dropped an invalid `SearchAction` target, rebranded `Lucode` → `Grove Starlight`, and corrected the GitHub org from `grove-dev/grove` to `tortuvshin/grove` across nine references.
- **v0.3.4 is the "we're shipping this" release** — config-driven `robots.txt` + `og-image.svg` with consumer-ownership transfer, GA4 analytics via `grove.config.ts`, and the last of the legacy cleanup.

## Grove is now a directory toolkit

The v0.2.x story was a single "V1" bundle: one CLI that scaffolded a fully-baked site, a `templates/default/` directory inside the package that was the source of every consumer site, and a parallel set of `nextjs` and `svelte` adapters that tried to keep parity. It worked for the first install. It did not work for the second, because every consumer wanted to change something fundamental — copy, section order, routes, branding — and the package was in the way.

So we split it.

### What `core` owns now

`@grove-dev/core` is now a framework-independent headless engine. Everything directory-shaped lives there: schema validation, taxonomy aggregation, filtering, sorting, pagination, lens rules, score labels, display formatting, repository metadata enrichment, contributor sync, sitemap generation, and `llms.txt` generation. The package exports a single default API plus a new browser-safe subpath:

```ts
import {
  loadConfig,
  validateProject,
  prepareDirectory,
  syncContributors,
} from "@grove-dev/core";
```

```ts
// packages/core/src/directory-client.ts — what a browser controller imports
export * from "./directory-display.js";
export * from "./directory-lenses.js";
export * from "./directory-search.js";
```

The `./directory` subpath deliberately excludes config loading, filesystem IO, validation, and generation. Client controllers reuse Grove's canonical filter, sort, and lens rules without dragging Node-only dependencies into the bundle.

### What `astro` owns now

`@grove-dev/astro` is the Astro adapter. It exposes Astro components, layouts, a Starlight plugin, sanitized Markdown rendering, and — new in v0.3.2 — a `server/models.ts` module that contains page view-models for consumers to import.

Pages no longer live in the package. They live in the consumer's repo. `grove init` copies `apps/example/` exactly once, and from that point on `src/pages/`, `src/layouts/`, and styling are your code. Grove's maintenance commands never overwrite them.

### What we deleted

This refactor removed more code than it added. The full diff is `+5,833 / −12,984`. The big deletions:

- `packages/{nextjs,svelte,ui}/` — adapters we never brought to parity.
- `packages/astro/templates/default/` — the package-owned scaffold. Its replacement is `apps/example/`, the same project but now living in `apps/` where it belongs.
- `packages/cli/src/index.ts` shrank from a sprawling multi-purpose file to a focused ~200-line orchestration layer for the four CLI commands.

### The CLI narrows to four commands

Every command is named after the part of the lifecycle it owns:

- `grove init [directory]` — scaffold a fresh Astro space from `apps/example/`.
- `grove check [--strict]` — validate records, generate artifacts, and run `astro check`.
- `grove sync <github|contributors>` — refresh the GitHub metadata that Grove owns.
- `grove cleanup` — write a report of records that need human review.

That's it. If you find yourself reaching for a fifth command, the answer is almost always "do it in the consumer repo, or in `core`."

### Repo layout: docs and example move under `apps/`

The repo went from `docs/` and `site/` at the root to `apps/docs/` and `apps/example/`. That makes `packages/` purely a packaging boundary — three publishable packages (`core`, `astro`, `cli`) plus the Starlight plugin — and `apps/` purely the workspace boundary — one docs application, one canonical example that doubles as the scaffold.

## The docs site gets a real home

`v0.3.1` is described in our changelog as a "docs-only patch" — the consumer-facing behavior, generated outputs, and schema were unchanged from `v0.3.0`. The work was entirely on the docs site itself, which had drifted away from what Grove actually shipped.

The headline change is `a3b3070f`: a full rewrite of the standalone home route. The previous home showed a fake `grove add` command, a fake `grove deploy` command, and an 8-framework logo wall that implied full support for everything (the CLI actually refuses `--framework svelte` and `--framework nextjs`).

The new home:

- **Real CLI lifecycle.** `import → structure → validate → enrich → review → publish → maintain`, with keyboard-operable tabs and per-stage CLI snippets that match the actual commands.
- **Honest framework matrix.** A 3-tier layout: *Supported today* (Astro), *Planned adapters* (SvelteKit, Next.js — rendered muted with grayscale logos), *Built on* (Tailwind, Node.js, GitHub — tooling, not adapters).
- **Real config file.** The terminal mock now shows `grove.config.ts`, the format that the scaffold actually writes.
- **Real sections wired to real headings.** Each `<section>` carries an `aria-labelledby` so assistive tech announces a clear landmark. Placeholder `#` anchors are gone — "Get Started" points at `/introduction/`, "View on GitHub" points at `https://github.com/tortuvshin/grove` in a new tab.

Underneath that landing rewrite we put real metadata on every page (`d542bcc1`):

```html
<!-- emitted by HomeLayout.astro and BaseLayout.astro -->
<meta property="og:type" content="website" />
<meta property="og:title" content="Grove" />
<meta property="og:image" content="https://grove.dev.mn/og-image.svg" />
<meta name="twitter:card" content="summary_large_image" />
<link rel="canonical" href="https://grove.dev.mn/" />
```

Plus three JSON-LD blocks (`WebSite`, `SoftwareApplication`, `Organization`) so search engines see Grove as a software product, a website, and an organization. A skip-to-content anchor sits above the home `<main>` landmark.

And the PWA plumbing landed too: `public/robots.txt` pointing at the canonical sitemap, a `public/manifest.json` for install metadata, a `public/_headers` file with CSP / X-Frame-Options / HSTS, and a canonical domain switch (`d201a238`) to `grove.dev.mn`. The standalone Astro + Tailwind home route (`7bc15ee0`) replaces the Starlight default and no longer depends on Starlight tokens, `BaseLayout`, or `Sidebar`.

## JSON-LD you can trust

Three small commits with outsized impact:

- **`a0312acc` — drop invalid `SearchAction` target.** The Starlight config emitted a JSON-LD `WebSite` schema with a `potentialAction.SearchAction.target` of `https://grove.dev.mn/search?q={search_term_string}`. That route returns 404 — Starlight ships a client-side search overlay only. Google's Rich Results guidelines flag an unreachable target as invalid structured data, so the block is gone until a real `/search` route exists.
- **`50259bec` — rebrand `Lucode` → `Grove Starlight`.** The Starlight plugin is ours. User-facing prose, code examples, test assertions, and the `@layer grove` CSS layer name now all reflect that. The old `LucodeStarlightUserConfig` and `LucodeDocsFrontmatter` types live on as `@deprecated` aliases.
- **`45c9b9c9` — fix the org name.** Nine references across six files pointed at `grove-dev/grove`, which returns 404. The real org is `tortuvshin` — same name used in `CONTRIBUTING.md`, `SECURITY.md`, and the GitHub releases.

These were surfaced by a post-launch audit (`public-claim-matrix.md`, `production-metadata-report.md`, `broken-link-report.md`). I'd rather catch this class of mistake at home than have a user find it.

## Consumer-facing hardening

The bulk of v0.3.x is a long tail of fixes that make a `grove init`'d project actually behave:

- **Validate record taxonomy references (`cf9ee7b4`)** — records that reference a missing category or stack now fail loudly instead of rendering silently.
- **Humanize unknown taxonomy labels (`4cc14b6d`)** — fallback labels read like English, not like a slug.
- **Modernize generated GitHub Actions (`7633fe20`)** — every workflow in `templates/default/.github/workflows/` uses a current Node and pnpm/action setup.
- **Keep generic scripts inside Grove (`916ae281`)** — `build-llms.mjs` and friends no longer leak into consumer repos.
- **Own contributor sync in Grove (`6f2dfdb7`)** — `syncContributors` lives in `core`; consumers get a stable public function instead of a copy.
- **Generate taxonomy display metadata (`d4c0c7e2`)** — display labels ship in the generated data so client code doesn't recompute them.
- **Fall back when icon assets are missing (`28a0d0f3`)** — `Icon.astro` no longer 404s on missing SVGs.
- **Hydrate static directory filters (`cb2195bd`)** — the URL-driven filter state survives an Astro static build.
- **Generate consumer-aware LLM URLs (`0c92b05f`)** — `llms.txt` and `llms-full.txt` use the configured site URL.
- **Type generated catalog JSON safely (`bdff4db2`)** — the import path returns a typed object.
- **Generate valid submission records (`e310f98c`)** — the submit page produces records that pass validation on the first try.
- **Export resource validation schemas (`f2de65a7`)** — `validateResource` and friends are public API.
- **Make Astro scaffold type-check (`1e8e3af5`)** — `pnpm exec astro check` passes on a fresh scaffold.
- **Honor configured routes and page content (`74f05544`)** — `src/pages/[slug]/index.astro` reads from config instead of hardcoding.
- **Align Grove workspace dependencies (`cd4f9b20`)** — `pnpm install` no longer leaves a phantom lockfile.

## v0.3.4 polish

v0.3.4 is what I'd call the "we're shipping this" release of the line. The headline PRs are all small, all focused on consumer ownership:

- **Config-driven site artifacts (`788898de`).** `packages/core/src/site-artifacts.ts` now generates `robots.txt` and `og-image.svg` from `grove.config.ts`. Both files are emitted with a marker comment — `# grove-generated: edit this file to take ownership` — so replacing the file with your own is a one-step "I own this now" action.
- **Site metadata from Grove config (`6dd48f08`).** `BaseLayout.astro` reads `site.url`, `site.name`, and `site.tagline` from `grove.config.ts`. The OG image dimensions, canonical URL, and theme color flow from the same source. A new `analytics.googleAnalyticsId` field threads GA4 into `BaseLayout.astro` — set it in config, get the script tag.
- **Custom icons without a package-owned registry (`39ff9ddb`).** `Icon.astro` and `IndexRow.astro` resolve SVG assets against the consumer's `public/icons/` directory. Add `apps/example/public/icons/stacks/tauri.svg` and `tauri` renders — no registry changes required. The same commit deduplicates `projectStackIds` so a record with two `Tauri` references renders once.
- **Paginated contributor sync (`33a75a79`).** `syncContributors` paginates GitHub's API instead of clipping to the first page. A repo with 1,200 contributors now syncs all 1,200.
- **Canonical build URL from config.** The build URL is no longer hardcoded; consumers can host a Grove site anywhere.
- **SmartLensTabs `allLabel` prop.** The "All" tab on curated lens tabs is now translatable.
- **Removal of legacy `/apps/[recordSlug].astro` route.** The package no longer ships a record-page route — every consumer owns their own record-page markup, and the test suite was updated to reflect that.

## Test coverage

Before v0.3.x, the only tests that ran in CI were a couple of scaffold smoke tests. Two commits changed that:

- `db5b21c2` — Vitest 4 wired into the workspace, with the `projects` array (Vitest 3's `defineWorkspace` API was removed in 4), and 91 unit tests for `@grove-dev/core` covering the V1 public surface.
- `88713f33` — 103 more tests across `@grove-dev/ui`, `@grove-dev/cli`, `@grove-dev/starlight`, plus a smoke test for `grove new`. Filter, sort, scoring, pagination, format, and CLI template loader each got their own file.

A non-obvious detail worth mentioning: TMPDIR is overridden to `./.tmp-test/` in the Vitest config because the opencode runtime sets `.opencode/tmp`, and the Vite SSR module loader was creating stale temp files there that broke later tests. This kind of detail is exactly what a test layer is supposed to surface.

## What's next?

The v0.3.x line closes the "toolkit" chapter. The next chapter is **v0.5.0**, and the roadmap I want to ship:

- **`grove import <url>` CLI.** Wrap the existing `importAwesomeList` + `writeImportedRecords` parser from `@grove-dev/core` so contributors can turn an awesome-list README into `data/records/<slug>.yml` files tagged `source: { type: "import" }`.
- **CI gates.** `pnpm test` as a separate `unit` job, plus a Starlight internal-link linter that walks every Markdown / MDX file and asserts each `/path/to/page/` target resolves to an existing `.md` file.
- **YAML loader hardening.** Every `parse(text)` call in `@grove-dev/core` now passes `{ schema: "core" }` so the `yaml` package does not interpret custom tags from untrusted input.
- **Lighthouse PR feedback.** Post a Markdown scorecard as a single update-in-place PR comment so budget regressions are visible at review time.
- **Edit links on docs pages.** `editLink.baseUrl` set explicitly to `https://github.com/tortuvshin/grove/edit/main/apps/docs/src/content/docs` so "Edit this page" resolves to the real source path.

v0.5.0 has no breaking changes for current consumers.
