# Default template for the Next.js framework adapter.

> Reserved for V1.2. The V1 CLI refuses `--framework nextjs` at scaffold time.

When V1.2 lands, the layout will be:

```txt
src/app/                    Next.js app router pages (list, detail, about, submit)
src/components/             Reusable components (port of the 22 V1 Astro surface)
src/data/                   Generated by `grove generate` (records.full.json, records.index.json, site-config.json)
public/                     Static assets (icons, llms.txt, robots.txt)
next.config.mjs
tsconfig.json
```

The CLI will copy this directory verbatim into a new project via `grove new --framework nextjs`. Pages and layouts live here; business logic lives in `@grove-dev/core` and `@grove-dev/ui` (V1: 5 typed primitives), and is imported into the template.

The template's `package.json` scripts chain the V1 CLI commands:

```jsonc
{
  "scripts": {
    "build:data": "grove generate",
    "build:sitemap": "grove sitemap",
    "build:llms": "grove llms",
    "build": "pnpm run build:data && pnpm run build:sitemap && pnpm run build:llms && next build"
  }
}
```

V0 command names (`grove build-data`, `grove build-llms-full`, `grove analyze`, `grove enrich`) are not used. The V1 names are: `grove generate`, `grove llms`, `grove sync github`.
