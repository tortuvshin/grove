<Aside type="tip" title="One dist/, many hosts">
  Grove emits a fully static `dist/` directory — no adapter, no output-mode override in `astro.config.mjs`. Any HTTP server that can serve files can host a Grove space: S3 + CloudFront, nginx, Caddy, Apache, or your own CDN. Pick the host you already operate; the build output doesn't care.
</Aside>

This page covers the recommended setups for common servers.

<Steps>

1. ## Build the site

   Before deploying, make sure `site.url` in `grove.config.ts` is your real production domain, or export `SITE_URL` in the shell that runs the build — `astro.config.mjs` reads `process.env.SITE_URL || groveConfig.site.url`. If neither resolves to a URL, the build fails: the shared `Seo` layout throws when `Astro.site` is unset, rather than shipping pages with links to a domain you don't own.

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="seti:notebook">
       ```bash
       SITE_URL=https://example.com pnpm build
       ```
     </TabItem>
     <TabItem label="npm" icon="seti:notebook">
       ```bash
       SITE_URL=https://example.com npm run build
       ```
     </TabItem>
     <TabItem label="bun" icon="seti:notebook">
       ```bash
       SITE_URL=https://example.com bun run build
       ```
     </TabItem>
   </Tabs>

   `pnpm build` is `astro build`. The Grove Astro integration prepares `data/generated/*.json`, `sitemap.xml`, `llms.txt`/`llms-full.txt`, `robots.txt`, and the OG images as part of that one command — no separate step is required. If you want the stricter pre-flight gate CI uses (schema validation plus `astro check`), run `pnpm exec grove check` first; it's optional for a self-hosted deploy, not required for `dist/` to be complete.

   The result is a fully static site in `dist/`: every record, collection, and page, plus the sitemap, `llms.txt`, and OG images — no server runtime needed to serve it.

2. ## Nginx

   ```nginx title="/etc/nginx/sites-available/grove.conf"
   server {
       listen 80;
       server_name example.com;
       root /var/www/grove/dist;
       index index.html;

       # build.format: 'directory' (astro.config.mjs) means every route
       # is a folder with an index.html, e.g. /projects/<slug>/index.html —
       # try_files needs the trailing-slash form to resolve directly.
       location / {
           try_files $uri $uri/ $uri.html /404.html;
       }

       # Long cache for hashed assets (Astro's default assets directory)
       location /_astro/ {
           expires 1y;
           add_header Cache-Control "public, immutable";
       }

       # Security headers
       add_header X-Content-Type-Options "nosniff" always;
       add_header Referrer-Policy "strict-origin-when-cross-origin" always;
   }
   ```

   `try_files` falls back to `404.html` (the scaffold ships `src/pages/404.astro`, which Astro's file-based routing turns into `dist/404.html`) so deep links resolve without a server-side router. Hashed assets under `/_astro/` are cached for a year with `immutable`; everything else uses nginx's default (no explicit cache policy set above — add one to taste).

3. ## Caddy

   ```text title="/etc/caddy/Caddyfile"
   example.com {
       root * /var/www/grove/dist
       encode gzip zstd
       try_files {path} {path}.html /404.html

       @assets path /_astro/*
       header @assets Cache-Control "public, max-age=31536000, immutable"
   }
   ```

   Caddy's automatic HTTPS via Let's Encrypt makes this the lowest-friction option for self-hosters — standard Caddy behavior, unrelated to Grove. `try_files` mirrors the nginx pattern above.

4. ## Apache

   ```apache title="/etc/apache2/sites-available/grove.conf"
   <VirtualHost *:80>
       ServerName example.com
       DocumentRoot /var/www/grove/dist
       <Directory /var/www/grove/dist>
           AllowOverride All
       </Directory>
   </VirtualHost>
   ```

   With `.htaccess`:

   ```apache title="/var/www/grove/dist/.htaccess"
   RewriteEngine On
   RewriteCond %{REQUEST_FILENAME} !-f
   RewriteCond %{REQUEST_FILENAME} !-d
   RewriteRule ^(.*)$ /$1.html [L]

   <IfModule mod_expires.c>
       ExpiresByType application/javascript "access plus 1 year"
       ExpiresByType text/css "access plus 1 year"
   </IfModule>
   ```

   <Aside type="caution" title="Common pitfalls">
     - `mod_rewrite` must be enabled (`a2enmod rewrite`) and `AllowOverride All` must be set in the `<Directory>` block — without it, the `.htaccess` is silently ignored.
     - Grove doesn't generate `public/.htaccess` — if you want one shipped inside `dist/`, add it to `public/.htaccess` yourself; Astro copies everything under `public/` into `dist/` unchanged.
     - The `<IfModule mod_expires.c>` block is a no-op without `mod_expires` enabled (`a2enmod expires`).
   </Aside>

5. ## S3 + CloudFront

   <Tabs syncKey="shell">
     <TabItem label="Sync and invalidate" icon="rocket">
       ```bash
       aws s3 sync dist/ s3://example.com --delete
       aws cloudfront create-invalidation --distribution-id E123 --paths "/*"
       ```
     </TabItem>
     <TabItem label="Bucket website config" icon="setting">
       ```bash
       aws s3 website s3://example.com \
         --index-document index.html \
         --error-document 404.html
       ```
     </TabItem>
   </Tabs>

   Set bucket website hosting to redirect unknown paths to `/404.html`.

   <Aside type="caution" title="Common pitfalls">
     - CloudFront invalidation is required after every deploy — S3 has no built-in cache-busting, but the edge does.
     - The `--delete` flag on `aws s3 sync` removes stale files from the bucket; without it, removed records keep serving from the bucket (and edge cache) until you clean them up manually.
     - The S3 website endpoint only supports HTTP; serve TLS through CloudFront.
   </Aside>

6. ## Local preview

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="seti:notebook">
       ```bash
       pnpm build
       pnpm preview
       ```
     </TabItem>
     <TabItem label="npm" icon="seti:notebook">
       ```bash
       npm run build
       npm run preview
       ```
     </TabItem>
     <TabItem label="bun" icon="seti:notebook">
       ```bash
       bun run build
       bun run preview
       ```
     </TabItem>
   </Tabs>

   `astro preview` (the scaffold's `preview` script) serves `dist/` on a local port and renders the production build exactly as your host will. Walk through every page before pushing.

</Steps>
