<Aside type="tip" title="Netlify as a deploy target">
  Netlify shines for static sites with PR previews, branch deploys, and edge functions. No Astro adapter is required — Grove's build is fully static, and `dist/` is a normal Netlify publish directory.
</Aside>

Grove spaces deploy to Netlify with no adapter. Grove doesn't ship a `netlify.toml` in the scaffold (`grove init` doesn't write one) — you author it once, or configure the equivalent settings in the Netlify UI.

<Aside type="note" title="Prerequisites">
  - A Netlify account (the free tier works).
  - A Grove space that builds to `dist/` via `pnpm build`.
  - Node 24, matching what `deploy.yml` uses for GitHub Pages (set via `NODE_VERSION` env var or `netlify.toml`).
  - Optional: a custom domain you control for production hosting.
</Aside>

## Configuration

`netlify.toml` at the project root (a file you write — Grove ships none):

```toml title="netlify.toml"
[build]
  command = "pnpm build"
  publish = "dist"

[build.environment]
  NODE_VERSION = "24"

[[headers]]
  for = "/*"
  [headers.values]
    X-Content-Type-Options = "nosniff"
    Referrer-Policy = "strict-origin-when-cross-origin"
```

`pnpm build` is `astro build`. The Grove Astro integration generates `data/generated/*.json`, `sitemap.xml`, `llms.txt`/`llms-full.txt`, `robots.txt`, and the OG images as part of that one command — there's no separate `grove check` step required for the build to produce a complete site. (`grove check` adds schema validation and `astro check` on top; it's what `ci.yml` runs on pull requests, not something the deploy needs.)

## Build settings

<Steps>

1. **Build command:** `pnpm build`
2. **Publish directory:** `dist`
3. **Node version:** 24 (via `NODE_VERSION` in `[build.environment]`, or the Netlify UI's Node version setting)
4. **Environment variable:** `SITE_URL` — set in Site settings → Environment variables (or `[build.environment]` in `netlify.toml`, though a real secret-free value like a URL is fine either place). `astro.config.mjs` reads `process.env.SITE_URL || groveConfig.site.url`; without either set to a real URL, the build fails — the shared `Seo` layout throws when `Astro.site` is undefined, rather than shipping a page with links to a domain you don't own.

</Steps>

## Custom domain

<Steps>

1. Add the domain in the Netlify admin panel (Domain management).
2. Set `SITE_URL` to match, or update `site.url` in `grove.config.ts` and rebuild.

</Steps>

Netlify issues a Let's Encrypt certificate automatically once DNS points at the assigned hostname — standard Netlify behavior, unrelated to Grove.

## Headers and redirects

Use `_headers` and `_redirects` files in `public/` for static rules (Netlify reads these from the published directory), or the `[[headers]]` block in `netlify.toml` for build-time configuration. Grove doesn't generate either file — add them yourself if you need custom caching or redirect rules beyond what `astro.config.mjs`'s `redirects` option covers.
