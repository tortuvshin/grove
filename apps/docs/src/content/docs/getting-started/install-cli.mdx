The Grove CLI (`@grove-dev/cli`) is the single tool you use to scaffold a space, validate records, and sync GitHub metadata. You don't need to install anything permanently — `pnpm dlx` fetches the latest on every run.

<Aside type="note" title="Prerequisites">
  - Node `>=22.12.0`
  - pnpm `10.12.1` (or a compatible Node package manager — npm, yarn, or bun work too)
</Aside>

## Verify your environment

Run these commands to confirm your toolchain is ready before installing.

<Tabs syncKey="shell">
  <TabItem label="bash">
    ```bash
    node --version    # v22.12.0 or higher
    pnpm --version    # 10.12.1 or compatible
    corepack enable   # one-time, only if pnpm isn't installed yet
    ```
  </TabItem>
  <TabItem label="fish">
    ```fish
    node --version    # v22.12.0 or higher
    pnpm --version    # 10.12.1 or compatible
    corepack enable   # one-time, only if pnpm isn't installed yet
    ```
  </TabItem>
  <TabItem label="PowerShell">
    ```powershell
    node --version    # v22.12.0 or higher
    pnpm --version    # 10.12.1 or compatible
    corepack enable   # one-time, only if pnpm isn't installed yet
    ```
  </TabItem>
</Tabs>

If `node --version` is below `22.12.0`, install a newer Node first — see [Troubleshooting](#node-version-is-too-old) below.

## Three install paths

Pick whichever matches your workflow.

<Steps>

1. ## Path A — `dlx` / `npx` / `bunx` (recommended; zero install)

   <Aside type="tip" title="Zero-install path">
     Run any command without permanently installing anything. `dlx` fetches the latest CLI on demand and uses a cache for repeat calls.
   </Aside>

   <Aside type="note" title="The CLI follows your package manager">
     `grove init` detects whether you are on pnpm, npm, yarn or bun — from the project you run it in, or from the command that launched it — and scaffolds for that one. It records the choice as `packageManager` in the generated `package.json`, installs the UI registry item with it, and prints the next steps in its wording. No package manager is required beyond the one you already use.
   </Aside>

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dlx @grove-dev/cli@latest init my-space
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npx @grove-dev/cli@latest init my-space
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bunx @grove-dev/cli@latest init my-space
       ```
     </TabItem>
   </Tabs>

   After this single command, you have a working `my-space/` directory. Every subsequent command is also a `dlx` call:

   ```bash
   pnpm dlx @grove-dev/cli@latest check
   pnpm dlx @grove-dev/cli@latest sync github
   ```

2. ## Path B — Global install

   <Aside type="tip" title="Persistent binary on your PATH">
     If you'd rather have a persistent `grove` binary on your `PATH`, install the CLI globally. The binary name is `grove`.
   </Aside>

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm add -g @grove-dev/cli
       grove --help
       grove init my-space
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npm install -g @grove-dev/cli
       grove --help
       grove init my-space
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bun add -g @grove-dev/cli
       grove --help
       grove init my-space
       ```
     </TabItem>
   </Tabs>

   All examples in the docs use this form, but every command also works as `pnpm dlx @grove-dev/cli@latest <command>`.

3. ## Path C — `npm`/`npx` (non-pnpm users)

   <Aside type="tip" title="For non-pnpm users">
     If you don't use pnpm, the same package works through `npx`. There's no functional difference. The CLI is published as `@grove-dev/cli` on npm.
   </Aside>

   <Tabs syncKey="pkg">
     <TabItem label="npm" icon="npm">
       ```bash
       npx @grove-dev/cli@latest init my-space
       ```
     </TabItem>
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dlx @grove-dev/cli@latest init my-space
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bunx @grove-dev/cli@latest init my-space
       ```
     </TabItem>
   </Tabs>

</Steps>

## Verify the install

The first scaffold command is `grove init`. Once you've run it (or installed globally), confirm the binary works:

```bash
grove --version
grove --help
```

Expected output (excerpt — the version number and column widths vary by release):

```text
$ grove --version
0.x.y

$ grove --help
Usage: grove [options] [command]

Commands:
  init [options] [directory]   Create a complete Grove directory from the official site.
  check [options]              Validate data, generate artifacts, and run Astro checks.
  sync [options] <target>      Refresh GitHub metadata owned by Grove.
  cleanup [options]            Write a report of records that need human review.
  collection                   Curated collection management
  readme                       Generate an awesome-list formatted README from data/records/.
  ...
```

If you see `command not found: grove`, see [Troubleshooting](#command-not-found-grove) below.

## Update the CLI

For `dlx` / `npx` users, the `@latest` tag always fetches the newest version — no update step needed.

For global installs, pick your package manager:

## Troubleshooting

### `command not found: grove`

<Aside type="caution" title="`command not found: grove`">
  The global install put the binary somewhere not on your `PATH`. Find where:

  ```bash
  pnpm bin -g
  ```

  Add the printed directory to your shell `PATH` (usually in `~/.zshrc` or `~/.bashrc`):

  ```bash
  export PATH="$(pnpm bin -g):$PATH"
  ```

  Or just use Path A (`pnpm dlx`) and skip the global install.
</Aside>

### Node version is too old

<Aside type="caution" title="Node version is too old">
  If you see `engine 'node' is incompatible with this package`, your Node is below `22.12.0`. Install a newer one:

  ```bash
  nvm install 22.12.0   # if you use nvm
  nvm use 22.12.0
  node --version        # confirm v22.12.0+
  ```
</Aside>

### `EACCES` on global install

<Aside type="caution" title="`EACCES` on global install">
  macOS / Linux global installs sometimes hit a permissions error. Two fixes:

  1. Use Path A (`pnpm dlx`) — no global install needed.
  2. Reconfigure pnpm to install globally under your home directory: `pnpm setup`.
</Aside>
