<Aside type="note" title="What grove.config.ts does">
  `grove.config.ts` is the single source of truth for your space. Edit it to change the site name, blueprint, theme, browse facets, integrations, and navigation. Every field is validated against the Zod schema when the config loads — a typo fails immediately with a clear message.
</Aside>

## The file in one view

A filled-in example, covering the fields you'll touch most:

```ts title="grove.config.ts"
import { defineConfig } from "@grove-dev/core";

export default defineConfig({
  blueprint: "project-directory",
  site: {
    name: "My Directory",
    tagline: "One line about what this is.",
    url: "https://mydir.dev",
    repoUrl: "https://github.com/me/mydir",
    description: "A longer description for OG cards and JSON-LD.",
  },
  theme: {
    primaryColor: "#0ea5e9",
    radius: "soft",
    density: "comfortable",
    containerWidth: "80rem",
  },
  browse: {
    facets: ["category", "stack", "platform", "tags", "license"],
  },
  integrations: {
    github: { metadata: true, contributors: true },
  },
  nav: [
    { label: "Home", href: "/" },
    { label: "Browse", href: "/projects" },
    { label: "About", href: "/about" },
  ],
});
```

The full field reference is in **[grove.config.ts reference](/reference/config/)**.

<Steps>

1. ### Blueprint

   `blueprint` decides what `kind` your records use and which templates render them. **`project-directory` is the only supported value today** — `grove init` always scaffolds it, and its records are `kind: project`:

   ```ts
   blueprint: "project-directory"
   ```

   The Zod schema also defines a `resource-hub` and an `ecosystem-map`
   blueprint (`kind: resource` and `kind: entity`), but neither has a
   supported scaffold or template yet — see the
   [roadmap](/project/roadmap/#later--directional). The blueprint and the record
   `kind` must match. See [Record schema](/reference/record-schema/) for
   the fields `kind: project` accepts.

2. ### Site identity

   These four fields flow into `<title>`, OG cards, canonical URLs, and JSON-LD:

   ```ts
   site: {
     name: "My Directory",
     tagline: "A focused list of tools we trust.",
     url: "https://mydir.dev",
     repoUrl: "https://github.com/me/mydir",
   }
   ```

   - `site.url` is the canonical base for every record's `<link rel="canonical">` and `og:url`. **If you omit it, OG tags resolve to `https://example.com`** and search engines treat every page as the canonical version.
   - `site.repoUrl` points at *your site's* repository — it drives the submit-a-record page's "open a pull request" link, the contributors page, and the `sync contributors` fallback. Per-record stars/forks come from each record's own `repoUrl` field, not this one.
   - `site.description` is optional but recommended — it populates the site-wide JSON-LD.

3. ### Theme tokens

   Tweak the visual feel without writing CSS:

   ```ts
   theme: {
     primaryColor: "#0ea5e9",
     radius: "soft",          // "none" | "soft" | "round"
     density: "comfortable",  // "compact" | "comfortable" | "spacious"
     containerWidth: "80rem", // any CSS length
   }
   ```

   See [Theme tokens](/customize/theme/) for the full list of tokens and what each controls.

4. ### Browse facets

   `browse.facets` chooses which dimensions appear as filters on the browse page (`/projects/` by default) and in what order:

   ```ts
   browse: {
     facets: ["category", "stack", "platform", "tags", "license"],
   }
   ```

   Only the canonical facet ids are accepted. **A typo fails config parsing immediately with a list of accepted ids.**

   <CardGrid>
     <Card title="category">
       Top-level grouping sourced from `data/taxonomy/categories.yml`. One per record.
     </Card>
     <Card title="stack">
       Tech-stack chips sourced from `data/taxonomy/stacks.yml`. Multiple per record.
     </Card>
     <Card title="platform">
       Platform filter chips sourced from `data/taxonomy/platforms.yml`.
     </Card>
     <Card title="tags">
       Free-form labels for filtering. Multiple per record; not backed by a taxonomy file.
     </Card>
     <Card title="license">
       License chips sourced from `data/taxonomy/licenses.yml`. Multiple per record.
     </Card>
   </CardGrid>

   See [Organize with taxonomy](/content/taxonomy-files/) for the taxonomy file shape each facet reads from.

5. ### Integrations

   Toggle which automated behaviors are enabled:

   ```ts
   integrations: {
     github: {
       metadata: true,     // refresh stars, forks, language, topics, license
       contributors: true, // aggregate contributor counts
       health: true,       // derive health.status from the fetched metadata
     },
   }
   ```

   None of these strictly require a `GITHUB_TOKEN` — `sync github` and `sync contributors` fall back to GitHub's unauthenticated API (60 requests/hour) and, if that's exhausted, an HTML scrape. Set `GITHUB_TOKEN` in `.env` to raise the rate limit and skip the fallback. See [Sync GitHub metadata](/automation/sync-github/) for setup.

6. ### Navigation

   Define the header nav. Each entry has a label and an href:

   ```ts
   nav: [
     { label: "Home",   href: "/" },
     { label: "Browse", href: "/projects" },
     { label: "About",  href: "/about" },
   ]
   ```

   The order of entries is render order. Each entry is just `label` and `href` — point `href` at a full URL for an off-site link. (The `external: true` flag exists on `footer.columns[].items`, not on top-level `nav`.)

</Steps>

## After editing

Config is read at boot, not hot-reloaded. After any change:

<Steps>

1. **Restart `pnpm dev`** — config changes don't apply until the next server boot.
2. **Run `pnpm exec grove check`** — validates the new config against the Zod schema and surfaces typos.
3. **Run `pnpm build`** — confirms the production build accepts it.

</Steps>

## Common mistakes

<Aside type="caution" title="site.url not set">
  OG tags resolve to `https://example.com`, JSON-LD `url` is wrong.
</Aside>

<Aside type="caution" title="`kind` other than `project`">
  `project-directory` is the only supported blueprint, and its records must be `kind: project`. A record with `kind: resource` or `kind: entity` fails Zod validation — it's parsed against that kind's schema instead, which requires fields (`title`/`type`/`topic`, or `name`/`type`) a project record doesn't have.
</Aside>

<Aside type="caution" title="Custom facet id (e.g. `categories`)">
  Fails with a list of accepted ids (`category`, `stack`, `platform`, `tags`, `license`).
</Aside>

<Aside type="caution" title="integrations.github.metadata: true without GITHUB_TOKEN">
  Not an error — `sync github` still runs against GitHub's unauthenticated API, rate-limited to 60 requests/hour, with an HTML-scrape fallback if that's exhausted. The build always succeeds either way; set `GITHUB_TOKEN` if syncing hits the rate limit.
</Aside>
