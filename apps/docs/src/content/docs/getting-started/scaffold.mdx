This is the long-form version of the [quickstart](/start-here/quickstart/)'s scaffold-and-first-run steps — what `grove init` actually does, what lands on disk, and why. If you already know the CLI and just want the commands, use the quickstart instead.

<Aside type="tip" title="What `grove init` produces">
  A complete Astro project: a directory layout with `data/records/`, `data/taxonomy/`, `data/collections/`, `grove.config.ts`, `astro.config.mjs`, GitHub workflow templates, and a sample site you can run with `pnpm dev`. The CLI copies the canonical Astro template, rewrites `package.json` (name and Grove dependency versions) and `grove.config.ts` (site name) to match your directory, then runs `pnpm install` and `git init` — unless you pass `--no-install` or `--no-git`.
</Aside>

## Requirements

See [Install the CLI](/getting-started/install-cli/) for the Node and pnpm versions Grove needs, and how to verify your toolchain before continuing.

## Create the project

<Steps>

1. ## Scaffold the directory

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dlx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bunx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     A new `my-directory/` folder on disk, populated with `data/`, `public/`, `src/`, `.github/`, `grove.config.ts`, and `astro.config.mjs`. The CLI prints a short summary of what was copied and modified.
   </Aside>

2. ## Confirm dependencies are installed

   `grove init` already ran `pnpm install` for you as its last step — you don't need to run it again unless you passed `--no-install`. `cd` in and check:

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       cd my-directory
       pnpm install   # only needed if you passed --no-install
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       cd my-directory
       npm install    # only needed if you passed --no-install
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       cd my-directory
       bun install     # only needed if you passed --no-install
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     `node_modules/` already populated from the `init` run. Re-running install is safe — it's a no-op if nothing changed, and it's what pulls everything in if you used `--no-install`.
   </Aside>

3. ## Start the dev server

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dev
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npm run dev
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bun run dev
       ```
     </TabItem>
   </Tabs>

   Open `http://localhost:4321`. You now have a working directory with example projects, search, filters, and project detail pages.

   <Aside type="note" title="What you should see">
     Astro prints `Local: http://localhost:4321/` and a network URL. The directory renders with six sample records so you can see how the layout works before you replace them.
   </Aside>

</Steps>

## What gets generated

<FileTree>
- my-directory/
  - data/
    - records/ directory entries (one YAML per record)
    - taxonomy/ categories, stacks, platforms, licenses, topics
    - collections/ curated collections
    - health.yml per-record health/maturity signals
    - generated/ build output (gitignored except contributors.json and repo-stats.json; rebuilt by grove check)
  - content/
    - records/ optional long-form Markdown body per record
  - public/
    - icons/, logo.svg kept from the template
    - robots.txt, og-image.svg, llms.txt, sitemap.xml, og/ written on first build (gitignored)
  - src/
    - pages/ home, [slug]/ (browse + record detail), categories/, stacks/, licenses/, collections/, submit, 404
    - components/ override any default Astro component
    - styles/global.css
  - .github/
    - workflows/ ci, cleanup, deploy, readme, sync-github, sync-contributors
    - ISSUE_TEMPLATE/
  - grove.config.ts site config (blueprint, site, theme, integrations)
  - astro.config.mjs
</FileTree>

Three files matter most:

- **`data/records/`** — your directory entries. One YAML file per record.
- **`grove.config.ts`** — site config. Name, blueprint, theme tokens, GitHub integration toggle, audit manifest.
- **`src/pages/`** — pages and UI customization. Override components here.

## `grove init` options

The CLI takes a single positional `[directory]` argument and two flags:

```bash
pnpm dlx @grove-dev/cli@latest init [directory] [--no-install] [--no-git]
```

| Flag | Effect |
| --- | --- |
| `--no-install` | Skip `pnpm install` after scaffolding. |
| `--no-git` | Skip `git init` after scaffolding. |

Omit `[directory]` to scaffold into the current directory (which must be empty). The scaffolder asks no prompts — site name, theme, and integrations are all chosen afterwards by editing `grove.config.ts`.
