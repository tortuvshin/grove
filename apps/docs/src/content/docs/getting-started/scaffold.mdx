This is the long-form version of the [quickstart](/start-here/quickstart/)'s scaffold-and-first-run steps — what `grove init` actually does, what lands on disk, and why. If you already know the CLI and just want the commands, use the quickstart instead.

<Aside type="tip" title="What `grove init` produces">
  A working Astro project: the `@grove/default` UI scaffold installed into `src/` from Grove's [component registry](/concepts/registry/), plus `package.json`, `grove.config.ts`, and `astro.config.mjs` generated for your directory. The CLI is a thin bootstrapper — it materializes the registry scaffold (no second template lives in the CLI itself), writes those three config files, then runs `pnpm install` and `git init` — unless you pass `--no-install` or `--no-git`.
</Aside>

## Requirements

See [Install the CLI](/getting-started/install-cli/) for the Node and pnpm versions Grove needs, and how to verify your toolchain before continuing.

## Create the project

<Steps>

1. ## Scaffold the directory

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dlx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bunx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     A new `my-directory/` folder on disk: `src/` (the installed registry scaffold), `package.json`, `grove.config.ts`, `astro.config.mjs`, and `.grove/registry.lock.json` (the install-time record `grove update` diffs against later). The CLI prints what it created.
   </Aside>

2. ## Confirm dependencies are installed

   `grove init` already ran `pnpm install` for you as its last step — you don't need to run it again unless you passed `--no-install`. `cd` in and check:

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       cd my-directory
       pnpm install   # only needed if you passed --no-install
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       cd my-directory
       npm install    # only needed if you passed --no-install
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       cd my-directory
       bun install     # only needed if you passed --no-install
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     `node_modules/` already populated from the `init` run. Re-running install is safe — it's a no-op if nothing changed, and it's what pulls everything in if you used `--no-install`.
   </Aside>

3. ## Start the dev server

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dev
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npm run dev
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bun run dev
       ```
     </TabItem>
   </Tabs>

   Open `http://localhost:4321`. You now have a working directory site — home, browse, and record-detail pages, search, and filters — with no records in it yet.

   <Aside type="note" title="What you should see">
     Astro prints `Local: http://localhost:4321/` and a network URL. The browse page renders its empty state, since `grove init` doesn't seed any sample data — add your first record next to see it populated.
   </Aside>

</Steps>

## What gets generated

<FileTree>
- my-directory/
  - src/
    - components/
      - ui/ primitives — button, badge, empty-state, search-field, …
      - grove/ domain UI — project-card, collection-index, hero, …
      - site/ site chrome — theme-toggle
    - layouts/ base-layout, header, footer, container, seo
    - pages/ home, browse, record detail, taxonomy, collections, submit, about, 404
    - lib/ classnames, icon registry — UI-local helpers
    - styles/system.css design tokens, light/dark theme, Tailwind theme
  - .grove/
    - registry.lock.json install-time file hashes — what `grove update` diffs against
  - package.json Grove packages + the scaffold's own deps (astro, tailwindcss, …), pinned/latest
  - grove.config.ts site config (blueprint, site, theme, integrations)
  - astro.config.mjs registers the Grove integration and the Tailwind Vite plugin
</FileTree>

Everything under `src/` is copied from Grove's [component registry](/concepts/registry/) — it's yours to edit freely. `grove update` will offer upstream improvements later without overwriting anything you've changed; see [Update a scaffold](/concepts/registry/) for how that works.

Three files matter most going forward:

- **`grove.config.ts`** — site config. Name, blueprint, theme tokens, GitHub integration toggle, audit manifest.
- **`src/components/`** — your UI. Edit anything here directly; there's no build step between the file and the rendered page.
- **`data/records/`** — your directory entries, one YAML file per record. You create this directory yourself — see [Add your first record](/getting-started/first-record/), next.

## `grove init` options

The CLI takes a single positional `[directory]` argument and two flags:

```bash
pnpm dlx @grove-dev/cli@latest init [directory] [--no-install] [--no-git]
```

| Flag | Effect |
| --- | --- |
| `--no-install` | Skip `pnpm install` after scaffolding. |
| `--no-git` | Skip `git init` after scaffolding. |

Omit `[directory]` to scaffold into the current directory (which must be empty). The scaffolder asks no prompts — site name, theme, and integrations are all chosen afterwards by editing `grove.config.ts`.
