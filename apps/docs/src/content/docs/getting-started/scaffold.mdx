<Aside type="tip" title="What `grove init` produces">
  A complete Astro project: a directory layout with `data/records/`, `data/taxonomy/`, `data/collections/`, `grove.config.ts`, `astro.config.mjs`, GitHub workflow templates, and a sample site you can run with `pnpm dev`. The CLI copies the canonical Astro template, rewrites `package.json` and `grove.config.ts` so `site.name` and the `name:` field match your directory, and runs `pnpm install`.
</Aside>

## Requirements

<Aside type="note" title="Prerequisites">
  - **Node.js** `>=22.12.0` (every Grove package and `apps/example` declare this in `engines`).
  - **pnpm** `10.12.1` — install via `corepack enable && corepack prepare pnpm@10.12.1 --activate`.
</Aside>

## Create the project

<Steps>

1. ## Scaffold the directory

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dlx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bunx @grove-dev/cli@latest init my-directory
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     A new `my-directory/` folder on disk, populated with `data/`, `public/`, `src/`, `.github/`, `grove.config.ts`, and `astro.config.mjs`. The CLI prints a short summary of what was copied and modified.
   </Aside>

2. ## Install dependencies

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       cd my-directory
       pnpm install
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       cd my-directory
       npm install
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       cd my-directory
       bun install
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     `node_modules/` populated, `pnpm-lock.yaml` (or equivalent) generated, no `ELIFECYCLE` errors. If you used `--no-install`, this is the step that pulls everything in.
   </Aside>

3. ## Start the dev server

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="pnpm">
       ```bash
       pnpm dev
       ```
     </TabItem>
     <TabItem label="npm" icon="npm">
       ```bash
       npm run dev
       ```
     </TabItem>
     <TabItem label="bun" icon="bun">
       ```bash
       bun run dev
       ```
     </TabItem>
   </Tabs>

   Open `http://localhost:4321`. You now have a working directory with example projects, search, filters, and project detail pages.

   <Aside type="note" title="What you should see">
     Astro prints `Local: http://localhost:4321/` and a network URL. The directory renders with six sample records so you can see how the layout works before you replace them.
   </Aside>

</Steps>

## What gets generated

<FileTree>
- my-directory/
  - data/
    - records/ directory entries (one YAML per record)
    - taxonomy/ categories / stacks / platforms
    - collections/ curated collections
    - decisions.yml curator visibility overrides
    - overrides.yml manual record patches
    - generated/ build output (gitignored; rebuilt by grove check)
  - public/ robots.txt, og-image.svg, llms.txt, sitemap.xml
  - src/
    - pages/ home, browse, [slug], submit, 404
    - components/ override any default Astro component
    - styles/global.css
  - .github/
    - workflows/ ci, cleanup, deploy, sync-github, sync-contributors
    - ISSUE_TEMPLATE/
  - grove.config.ts site config (blueprint, site, theme, integrations)
  - astro.config.mjs
</FileTree>

Three files matter most:

- **`data/records/`** — your directory entries. One YAML file per record.
- **`grove.config.ts`** — site config. Name, blueprint, theme tokens, GitHub integration toggle, audit manifest.
- **`src/pages/`** — pages and UI customization. Override components here.

## `grove init` options

The CLI takes a single positional `[directory]` argument and two flags:

```bash
pnpm dlx @grove-dev/cli@latest init [directory] [--no-install] [--no-git]
```

| Flag | Effect |
| --- | --- |
| `--no-install` | Skip `pnpm install` after scaffolding. |
| `--no-git` | Skip `git init` after scaffolding. |

Omit `[directory]` to scaffold into the current directory (which must be empty). The scaffolder does not ask prompts in `0.5.0-next.2` — the blueprint and integrations are chosen by editing `grove.config.ts` after scaffold.
