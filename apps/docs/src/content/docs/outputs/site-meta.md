This page covers the small set of metadata Grove actively emits and the things consumers provide themselves.

## What's emitted today

### `theme-color`

The `<meta name="theme-color">` tag is set in the Starlight `head:` config block. The docs site uses `#08090a` (a near-black). Consumer sites override via `site.twitter`, `theme.primaryColor`, or by replacing the Starlight `head:` block.

### `color-scheme`

`<meta name="color-scheme">` is set to `dark light` so browsers can render with the user's preferred scheme. Override via the consumer's Astro/Starlight config.

### `manifest.json`

The Starlight docs site references `<link rel="manifest" href="/manifest.json">` from its `head:` block. The manifest itself is consumer-provided — put a PWA manifest at `public/manifest.json`. The framework does not generate one.

### Apple touch icon

`<link rel="apple-touch-icon" href="/og-image.svg">` reuses the SVG OG fallback as the apple-touch icon. Replace by overriding the Starlight `head:` block.

## What consumers typically provide

These files are commonly expected on a website but are NOT generated by Grove. Add them under `public/` if your site needs them.

| File | Purpose | Notes |
|---|---|---|
| `public/manifest.json` | PWA manifest | Required if the site installs as a PWA. The Starlight docs site references it. |
| `public/security.txt` | Responsible disclosure | Place at `/.well-known/security.txt` to comply with the convention; the root path works too. |
| `public/humans.txt` | Credits / authorship tradition | Optional; not generated. |
| `public/feed.xml` | RSS feed | Not generated. A future framework extension might add this; for now, build from `public/llms-full.txt` or `records.json`. |
| `public/feed.json` | JSON Feed | Not generated. Use `data/generated/records.json` directly. |
| `public/.well-known/assetlinks.json` | Android PWA asset link | Optional; only needed for TWA-style installs. |
| `public/.well-known/apple-app-site-association` | iOS Universal Links | Optional; only needed for app-bound links. |

## Sentinel-owned files

The framework ships two files with sentinels that mark first-time generation:

| File | Sentinel |
|---|---|
| `public/robots.txt` | `<!-- grove-generated: edit this file to take ownership -->` |
| `public/og-image.svg` | `<!-- grove-generated: edit this file to take ownership -->` |

Once the file is edited, the sentinel is gone and Grove stops regenerating it. To restore the framework's behavior, delete the file and rebuild — the sentinel returns.

## Head metadata the framework reads

`grove.config.ts` provides the values that flow into per-page headers:

| Config field | Mapped to |
|---|---|
| `site.name` | `<title>`, JSON-LD `name`, OG `og:site_name` |
| `site.tagline` | `<meta name="description">` fallback |
| `site.description` | JSON-LD `description` |
| `site.url` | `<link rel="canonical">`, OG `og:url`, JSON-LD `url` |
| `site.locale` | `<html lang>`, `og:locale`, JSON-LD `inLanguage` |
| `site.twitter` | `twitter:site` |
| `theme.primaryColor` | `<meta name="theme-color">` (override at head level) |

If you change any of these, rebuild — the headers reflect the source of truth at build time.
