Grove emits a complete SEO baseline out of the box: `sitemap.xml`, `robots.txt`, JSON-LD on every page, and a default `og-image.svg` for social previews. This page covers each artifact and the planned upgrades.

## `sitemap.xml`

A `<urlset>` listing every public URL. Built by `buildSitemap` at `packages/core/src/sitemap.ts:71`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://example.com/</loc><lastmod>2026-08-14</lastmod></url>
  <url><loc>https://example.com/projects/</loc><lastmod>...</lastmod></url>
  <url><loc>https://example.com/projects/ollama/</loc><lastmod>...</lastmod></url>
  ...
</urlset>
```

### Sitemap index (planned)

For sites with >45,000 URLs, [sitemaps.org](https://www.sitemaps.org/protocol.html) requires splitting. Grove exports `buildSitemapIndex` (`packages/core/src/sitemap.ts:120`) but it's not yet wired into the pipeline. The plan:

- When `urlCount > 45,000`: emit `sitemap-index.xml` pointing at:
  - `sitemaps/records.xml` (record detail pages, gzipped)
  - `sitemaps/taxonomies.xml` (taxonomy landing pages)
  - `sitemaps/pages.xml` (about, contributors, submit, 404, content pages)
- Update `robots.txt` to point at `sitemap-index.xml`.

## `robots.txt`

Generated by `buildRobotsTxt` (`packages/core/src/robots.ts:3`). Includes ownership markers and is written through `writeOwnedArtifact` (only if absent). Default body:

```
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

### Cloudflare Content Signals (planned)

Add `Content-Signal: search=yes, ai-train=no, ai-input=yes` to the `User-agent: *` block.

## JSON-LD per page

Every page emits a `<script type="application/ld+json">` block.

| Page type | Schema.org type | Reference |
|---|---|---|
| Site-wide | `WebSite` + `Organization` | `packages/core/src/page-document.ts:120` |
| Record (project) | `SoftwareSourceCode` | `models.ts:389` |
| Record (resource) | `CreativeWork` | `models.ts:421` |
| Record (entity) | `Organization` / `Person` | `models.ts:437` |
| Collection | `ItemList` of `SoftwareApplication` | `collections.ts:166` |

Site-wide JSON-LD includes a `WebSite` schema with `publisher` and (where applicable) a `SearchAction`. SearchAction is omitted for sites using Starlight's client-side search overlay (no real `/search?q=` route) — Google's Rich Results Test flags unreachable targets as invalid.

## OG image

The current default is `og-image.svg`, a 1200×630 SVG generated by `buildOgImageSvg` (`packages/core/src/site-artifacts.ts:54`). It works in `<meta property="og:image">` and Twitter Card slots, but:

- **Facebook's Sharing Debugger won't reliably cache SVG** — previews may show as broken or stale.
- **LinkedIn and Slack handle SVG inconsistently** across versions.

### Per-page PNG OG (planned)

The recommended fix is per-page OG images at static build time using:

1. **HTML → SVG:** [satori](https://github.com/vercel/satori) (Vercel)
2. **SVG → PNG:** [`@resvg/resvg-js`](https://github.com/yisibl/resvg-js) for rasterization

Output: `/og/<slug>.png` at 1200×630 PNG, served from `<meta property="og:image" content=".../og/<slug>.png">`. Each record page gets its own preview; the SVG fallback remains for the homepage and as a fallback when build-time generation isn't possible.

## `<head>` tags emitted by Grove

Every page receives:

- `<title>` and `<meta name=description>`
- Canonical URL
- Open Graph: `og:type`, `og:url`, `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:site_name`, `og:locale`
- Twitter Card: `summary_large_image`
- Theme color (light + dark variants)
- Inline SVG favicon
- `<link rel="sitemap" href="/sitemap.xml">`
- `<link rel="alternate" type="text/plain" href="/llms.txt">` (planned; spec-compliant autodiscovery)
- `<meta name="robots" content="noindex">` opt-in
