This is the canonical "first 8 minutes" with Grove. By the end you will have a record you can see on the running site. The walkthrough assumes you've installed Node `>=22.12.0` and pnpm `10.12.1`. If not, see [Install the CLI](/getting-started/install-cli/).

<Aside type="tip" title="8 minutes, six steps, your first record on the live site.">
Six short steps take you from an empty directory to a record visible on the running site. The whole loop — scaffold, run, edit, validate, preview, push — fits in a coffee break. Work straight through; each step depends on the one before it.
</Aside>

<Aside type="note" title="Prerequisites">
- Node `>=22.12.0`
- pnpm `10.12.1` (or any compatible Node package manager — npm and bun tabs work too)
- A GitHub account, if you plan to push the result
</Aside>

<Steps>

1. ### Scaffold a space

   <Tabs syncKey="pkg">
     <TabItem label="pnpm" icon="seti:notebook">
       ```bash
       pnpm dlx @grove-dev/cli@latest init my-space
       cd my-space
       ```
     </TabItem>
     <TabItem label="npm" icon="seti:notebook">
       ```bash
       npx @grove-dev/cli@latest init my-space
       cd my-space
       ```
     </TabItem>
     <TabItem label="bun" icon="seti:notebook">
       ```bash
       bunx @grove-dev/cli@latest init my-space
       cd my-space
       ```
     </TabItem>
   </Tabs>

   <Aside type="note" title="What you should see">
     A `my-space/` directory with `data/`, `src/`, `public/`, `grove.config.ts`, and a sample of six records under `data/records/`.
   </Aside>

2. ### Start the dev server

   ```bash
   pnpm dev
   ```

   <Aside type="note" title="What you should see">
     Astro prints `Local: http://localhost:4321/`. Open that URL — your directory's homepage renders with the six sample records. Edits to `data/records/*.yml` rebuild within a few hundred milliseconds.
   </Aside>

3. ### Edit one of the sample records

   Open `data/records/ollama.yml` (or any sample). Replace the placeholder fields with your own:

   ```yaml title="data/records/my-record.yml"
   kind: project
   name: my-project
   description: One-line summary of what my-project does.
   repoUrl: https://github.com/me/my-project
   stacks: [typescript]
   licenses: [mit]
   ```

   <Aside type="note" title="What you should see">
     The dev server hot-reloads. The detail page at `http://localhost:4321/projects/my-project/` renders with your values.
   </Aside>

4. ### Validate the record

   ```bash
   pnpm exec grove check
   ```

   <Aside type="note" title="What you should see">
     The validator walks every record against the Zod schema. A clean run ends with `0 errors`. If your record fails, the output names the file, the field, and the expected type.
   </Aside>

5. ### See the record on the site

   Visit `http://localhost:4321/projects/my-project/`. The detail page should show:

   - The record's name, description, and category.
   - The "View repository" button (from `repoUrl`).
   - Stack and license chips (from `stacks` / `licenses`).
   - The auto-generated JSON-LD block in the page source (View → Inspect).

   The homepage index also lists the new record alphabetically.

   <Aside type="note" title="What you should see">
     The detail page renders your record with chips and a working repository link; the homepage alphabetically lists it alongside the other five sample records.
   </Aside>

6. ### Commit and open the PR

   ```bash
   git add data/records/my-project.yml content/records/my-project.md
   git commit -m "Add my-project"
   git push
   ```

   <Aside type="note" title="What you should see">
     GitHub Actions runs `grove check` plus `astro build`. If `integrations.github` is enabled, `sync-github.yml` enriches the record with live stars / language / last-pushed data on the next scheduled run. Merge the PR; the site rebuilds.
   </Aside>

</Steps>

## What just happened

<CardGrid stagger>
  <Card title="Directory layout" icon="seti:notebook">
    `my-space/` now contains a working scaffold — `data/`, `src/`, `public/`, `grove.config.ts` — and six sample records under `data/records/` that you can keep, replace, or delete.
  </Card>
  <Card title="Record file" icon="pencil">
    `data/records/my-project.yml` holds the canonical record (YAML schema, validated by Zod). The matching `content/records/my-project.md` is the optional long-form body.
  </Card>
  <Card title="Dev server" icon="rocket">
    `pnpm dev` boots Astro at `http://localhost:4321/`. Edits to `*.yml` rebuild in a few hundred milliseconds; the detail page and the homepage index both reflect changes immediately.
  </Card>
  <Card title="Validation" icon="setting">
    `pnpm exec grove check` walks every record against the schema and regenerates everything under `data/generated/` and `public/`. A clean run ends with `0 errors`.
  </Card>
</CardGrid>
