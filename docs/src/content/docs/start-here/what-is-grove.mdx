## What Grove Does

<CardGrid>
    <Card title="Spaces" icon="open-book">
        Grove Spaces are structured containers that hold the projects, tools, resources, and
        knowledge a community curates. Spaces are versioned, forkable, and easy to maintain.
    </Card>
    <Card title="Blueprints" icon="setting">
        Blueprints define the schema of a Space. They make contributions reviewable, keep quality
        consistent, and let contributors submit pull requests with confidence.
    </Card>
    <Card title="Open Source First" icon="rocket">
        Grove is MIT-licensed, framework-agnostic, and ships adapters for Astro, Next.js, and
        SvelteKit. The data lives in your repo, the tooling fits your existing CI.
    </Card>
    <Card title="Grow Over Time" icon="starlight">
        Grove treats knowledge like a long-lived artifact. Updates, refactors, and archival are
        first-class operations, not afterthoughts.
    </Card>
</CardGrid>

## How It Works

A Grove **Space** is a folder in your repo with structured records. Each record has a Blueprint
schema — the same way a database table has columns — and a Markdown file with prose, examples, and
links. Grove's CLI checks, formats, and upgrades records on every commit, so contributions stay
reviewable, consistent, and current.

<CardGrid>
    <Card title="1. Bootstrap" icon="rocket">
        Run `pnpm create grove` to scaffold a Space, pick an adapter (Astro, Next.js, SvelteKit),
        and connect it to your existing CI.
    </Card>
    <Card title="2. Author" icon="pencil">
        Add records as Markdown files. Blueprints enforce fields, link types, taxonomy, and
        required tags — so contributors cannot drift.
    </Card>
    <Card title="3. Maintain" icon="setting">
        Run `grove check` on every PR. Health scores, broken links, and stale records surface
        automatically. Refactors are first-class operations.
    </Card>
    <Card title="4. Deploy" icon="starlight">
        Ship a static site, a Next.js app, or a SvelteKit portal. Grove fits your existing stack —
        it never replaces it.
    </Card>
</CardGrid>

</ContainerSection>

## Built for the Long Run

<CardGrid>
    <Card title="Versioned records" icon="rocket">
        Every record has a `since` field and a changelog. Refactors are atomic PRs. Forks inherit
        schema history, not just the current state.
    </Card>
    <Card title="Decision logs" icon="open-book">
        Keep "why we use X" alongside "what we use." Decisions become searchable, reviewable, and
        referenceable from individual records.
    </Card>
    <Card title="Health checks" icon="heart">
        Stale links, missing fields, and abandoned records are surfaced automatically. CI fails
        before the problem reaches a reader.
    </Card>
    <Card title="Taxonomy" icon="puzzle">
        Tag records with curated labels, not free-form text. Categories stay small, useful, and
        consistent across years of contributions.
    </Card>
</CardGrid>

</ContainerSection>

## Pick Your Adapter

<CardGrid>
    <Card title="Astro" icon="starlight">
        The recommended adapter. Ship a fully static site with `astro build` and deploy it to any
        CDN. Starlight-compatible themes available out of the box.
    </Card>
    <Card title="Next.js" icon="right-arrow">
        For teams that need server components, edge runtime, or React. Grove integrates as a
        content source for your existing Next.js app.
    </Card>
    <Card title="SvelteKit" icon="puzzle">
        For Svelte-native teams. Same CLI, same data model, Svelte's component model for the
        rendered views.
    </Card>
    <Card title="Bring your own" icon="setting">
        Grove's data layer is framework-agnostic. The CLI emits JSON; you render it however you
        want.
    </Card>
</CardGrid>
