## Current status

Grove is in **active development** (current release: **v0.2.x**).

**End-to-end supported in V1:**

- The `project-directory` blueprint, the `project` record kind, and the Astro adapter (the default template ships a working directory site out of the box)
- File-based YAML records under `data/records/`
- The full CLI: `new`, `import`, `validate`, `generate`, `sitemap`, `llms`, `sync github`, `cleanup stale`, `workflows sync`, `build`, `dev`
- `llms.txt` and `sitemap.xml` output, wired into the Astro build pipeline
- GitHub workflows for CI validation, scheduled metadata sync, and stale-record reports

**Schema-ready, no template yet:**

- The `resource-hub` blueprint and the `resource` record kind
- The `ecosystem-map` blueprint and the `entity` record kind

The Zod schemas and CLI support exist for both, but the Astro template does not yet ship polished default pages for these kinds.

**Roadmap (not in V1):**

- The **Next.js** adapter — the package is reserved, but the default template is `package.json` only, and `grove build` refuses to run it.
- The **SvelteKit** adapter — same status as Next.js.
- The `@grove-dev/ui` framework-agnostic primitives — package reserved, no implementations.

## A note on honesty

Grove V1 supports the Astro adapter and the `project-directory` blueprint.
The Next.js and SvelteKit adapter packages exist to reserve the package
boundary, but they are not recommended for production use yet. The
`resource-hub` and `ecosystem-map` blueprints describe the schema
direction, but their default templates and polished workflows are still
experimental.

If you find a doc that says "supported" but the code says otherwise, that's
a bug — please [open an issue](https://github.com/grove-dev/grove/issues).
